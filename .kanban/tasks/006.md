## Задача

Реализовать `ContextLoader`: собрать контекст-пак воркспейса при открытии папки и
поддерживать его в актуальном состоянии.

- `extension/src/context/`: `AGENTS.md` в корне и вложенных каталогах (наследование
  с приоритетом ближайшего), `.dsh/workspace.json` (валидация схемой, неизвестные
  ключи — warn), скилы (`~/.dsh/skills`, `.dsh/skills`, `.agents/skills`),
  память проекта (если включена), индекс файлов.
- Индекс: уважает `.gitignore` и `context.ignore`/`maxBytes` из манифеста;
  не читает бинарники; считает размеры и языки.
- Кэш по хешу входов (mtime+size), инвалидация при изменении правил/скилов/
  манифеста, `git checkout`; watcher с debounce 500 мс.
- Приоритеты при конфликтах правил: проект > пользователь > встроенное;
  результат конфликта отдаётся инспектору (#013), а не молча затирается.
- Unit-тесты: вложенные AGENTS.md, битый манифест, игноры, кэш-хит/промах,
  hot reload по событию ФС.

## Критерии готовности

- [ ] Контекст-пак собирается для тестового проекта за < 300 мс на 1000 файлов.
- [ ] Изменение `AGENTS.md` инвалидирует кэш и обновляет панель (событие наружу).
- [ ] Секреты и игнорируемые файлы не попадают в пак (тест).
- [ ] `node --test` зелёный.

- **hot reload**: `fs.watch(recursive)` + debounce 500 мс, фильтр релевантных
  файлов (`AGENTS.md`, `.gitignore`, `.dsh/**`, `.agents/skills/**`), событие
  наружу с новым паком; `dispose()` закрывает watcher и сбрасывает кэш.

**`extension/src/context/README.md`** — API, состав пака, приоритеты, игноры,
лимиты, кэш и hot reload, границы.

### Почему одним файлом

Тесты импортируют `contextLoader.ts` напрямую (Node исполняет TypeScript), а
относительные импорты внутри extension пришлось бы писать с `.ts`-расширениями и
менять `extension/tsconfig.json` (#001) ради косметики. Модуль цельный; разделы
внутри файла: типы → игноры → манифест → правила/скилы → индекс → загрузчик →
помощники.

### Производительность

Критерий «< 300 мс на 1000 файлов»: обход дерева — один проход, `stat` в обходе
синхронный. Замеры на этой машине: холодная сборка 1002 файлов — **140 мс**,
повторная (кэш-хит) — 19–120 мс (в тесте `stats.durationMs` проверяется
assert'ом). Асинхронные 1000 `stat` через thread pool давали 200–650 мс с
большим разбросом — не проходили бюджет. Плата: синхронный обход блокирует
event loop на единицы миллисекунд; это операция старта/пересборки контекста, не
горячий путь.

## Исправления по замечаниям ревьювера (`ec7158a`)

1. **Память не читается за пределами воркспейса (безопасность).**
   `#memoryDirectory` теперь: `path.resolve` + проверка `isPathInside(root, …)`,
   затем `realpath` каталога и повторная проверка (симлинк наружу не проходит).
   `memory.path: "../outside"` и абсолютный путь снаружи дают предупреждение
   `manifestWarnings` и пустой `pack.memory`. Дополнительно память фильтруется
   от секретных имён. Тесты: `../outside`, абсолютный путь, (симлинк покрыт
   проверкой realpath).
2. **`rules`/`skills` из манифеста применяются.** `#loadRules` читает файлы из
   `manifest.rules` (с проверкой границ и дедупликацией по пути), `#skillsDirectories`
   добавляет каталоги из `manifest.skills`, `#validateManifest` даёт
   предупреждения для путей вне воркспейса и несуществующих файлов/каталогов.
   Тесты: правило из `docs/CONVENTIONS.md` попадает в пак, внешний и
   отсутствующий путь — предупреждения; скил из `.custom-skills` попадает,
   внешний каталог отбрасывается с предупреждением.
3. **`.git`-файл (git worktree) больше не индексируется.** Исключение по имени
   `entry.name === '.git'` до проверки типа записи, поэтому и каталог, и файл
   отбрасываются. Тест: workspace с `.git`-файлом — в индексе его нет.
4. **Мелочи:**
   - лимиты `rules`/`memory` считаются в байтах (`truncateToBytes`,
     `Buffer.byteLength`), а не в UTF-16-символах;
   - `ruleFiles` в хеше кэша теперь с `mtime`+`size` — изменение `AGENTS.md`,
     не попавшего в индекс из-за игноров, инвалидирует пак (тест);
   - `ContextConflict.kind` больше не содержит мёртвого варианта `'rule'` —
     правила не конфликтуют, они наследуются, конфликты остаются у скилов;
   - вложенные `.gitignore` по-прежнему не читаются (в README это ограничение
     названо явно: «`.gitignore` в корне»).
