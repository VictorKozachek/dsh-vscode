## Задача

Связать чат с выбранной сессией: сейчас панель живёт «одной сессией» и отвечает
эхом; нужно — история на сессию, переключение, стоп, статус.

- `extension/src/views/chat*`: чат слушает активную сессию из `SessionManager`;
  при переключении — заменяет историю (replay из транскрипта, если доступен,
  иначе с чистого листа с пометкой).
- `webview/src/chat/`: шапка показывает имя сессии, пресет, модель, статус;
  composer блокируется без активной сессии (CTA «Создать сессию»);
  «Стоп» шлёт `turn.cancel` именно активной сессии.
- Сохранение черновика composer на сессию; индикатор «Думает…» из статуса
  рантайма; ошибки рантайма — баннер с повтором.
- События `token`/`tool.call` маршрутизируются по `sessionId`: события чужой
  сессии не попадают в ленту (тест).
- Расход: токены/время хода в статусной строке панели (если рантайм отдаёт).

## Критерии готовности

- [ ] Две сессии — две независимые истории; переключение не смешивает сообщения.
- [ ] Стоп отменяет ход только активной сессии (тест).
- [ ] Composer без сессии заблокирован и ведёт в создание.
- [ ] События неактивной сессии отбрасываются (тест маршрутизации).
- [ ] Переключение сессии не теряет черновик (тест).

## Заметки исполнителя

### Сделано (закоммичено в `task/024`, коммит `fdc4417`)

**`extension/src/views/chatTranscript.ts`** — история на сессию
(`SessionTranscriptStore`): сообщения пользователя, накопление токенов в
assistant-сообщение, чтение/очистка по `sessionId`.

**`chatEvents.ts`** — `ChatController` принимает порт `ChatSessionsPort`
(снимок активной сессии, `getDraft`/`setDraft`, события
`sessionChanged`/`statusChanged`):
- события `token`/`tool.call`/`tool.result`/`turn.done`/`error` фильтруются по
  `sessionId` — события неактивной сессии отбрасываются;
- при переключении: `replaceMessages` из транскрипта (или пустая лента),
  `chatSession` (id/title/model/preset/status/`historyReplayed`),
  `composerDraft`; `turnId`/статус сбрасываются;
- `Стоп` шлёт `turn.cancel` только активной сессии и её ходу;
- `setDraft` сохраняет черновик, `requestNewSession`/`retry` — CTA и повтор;
- без порта сессий — прежнее поведение (совместимость с каркасом).

**Контракт** (`chatHtml.ts` + `webview/src/messages.ts`, паритет тестом):
extension→WebView `chatSession`/`composerDraft`; WebView→extension
`draftChanged`/`openNewSession`/`retryChat`; диспетчер маршрутизирует их в
порт `chatSession`, провайдер панели принимает порт.

**Webview** — `chat/drafts.ts` (черновик на сессию), шапка с именем сессии и
статусом, composer блокируется без активной сессии и показывает кнопку
«Создать сессию», баннер ошибки с «Повторить», пометка при недоступной
истории, отправка `draftChanged` при вводе. i18n ru/en.

### Тесты
