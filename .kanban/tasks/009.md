## Задача

Подтверждения и sandbox-политики: инлайн-диалоги вместо модальных окон.

- `webview/src/approvals/`: инлайн-карточка `approval.request` с кнопками
  «Разрешить», «Разрешить для этой сессии», «Отклонить», «Показать diff»;
  фокус-ловушка и клавиатура.
- `extension/src/approvals/`: политика `ask`/`auto`/`never` (per tool type),
  маппинг sandbox-режимов `read-only`/`workspace-write`/`danger-full-access`,
  обязательное подтверждение для записи вне воркспейса и сетевых вызовов.
- Аудит: `.dsh/audit.log` (JSONL, ротация по размеру), без секретов.
- Fallback: если панель скрыта — `vscode.window.showInformationMessage` с теми же
  действиями (не блокирующий модал).
- Тесты: разрешение политик, отклонение останавливает инструмент, аудит-запись.

## Критерии готовности

- [ ] «Отклонить» гарантированно останавливает инструмент (тест).
- [ ] `ask` для записи вне воркспейса даже при `auto` (тест).
- [ ] Аудит пишется, ротация работает, секретов нет.
- [ ] Тесты зелёные.

## Исправления по замечаниям ревьювера (`425c6a6`)

1. **`allow-session` больше не обходит политику.** Оценка политики и sandbox
   выполняется до сессионного разрешения; в `ApprovalEvaluation` добавлен
   `mandatory`, и «разрешить для сессии» сокращает только обычный `ask`. Запись
   вне воркспейса/сеть/неизвестный путь спрашиваются заново; `never` и
   `read-only` остаются запретами. Тест: после `allow-session` запись в
   `/tmp/evil.ts` снова спрашивает.
2. **Sandbox-запрет сильнее обязательного подтверждения.** В `read-only` запись
   и команды — `deny` даже вне воркспейса (раньше `ask` позволял разрешить).
   Тест на `read-only` + `/tmp/evil.ts` при `auto` и `ask`.
3. **Запись без `targetPath` не считается «внутри»:** путь неизвестен →
   обязательное подтверждение (`auto`) или запрет (`never`). Тест.
4. **Symlink.** В брокер добавлен `resolveRealPath`: targetPath резолвится перед
   проверкой границ, путь наружу становится обязательным подтверждением. Тест
   с резолвером `link/evil.ts → /outside/evil.ts`.
5. **Аудит без секретов.** `sanitizeForAudit` вычищает userinfo и query-строку
   URL; `targetPath` и `reason` тоже проходят очистку. Тест: `?token=SECRET` не
   попадает ни в один поле.
6. **Ошибка аудита не ломает решение.** Все записи идут через `#record` с
   catch+логом; `void`-вызовы больше не дают unhandled rejection. Тест с
   rejecting-аудитом.
7. **Producer `approvalResolved`.** У брокера появился `onResolved(request,
   decision)` — вызывается при любом settled-решении (fallback, dispose,
   WebView); по нему панель снимает карточку. Проводка в #011. Тесты для
   fallback и dispose.
8. **Source сессионных решений:** добавлен `AuditSource = 'session'`; повторное
   разрешение по сессии пишется с `source: 'session'`. Тест.
