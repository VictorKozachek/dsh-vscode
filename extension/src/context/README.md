# `extension/src/context` — ContextLoader

Собирает контекст-пак воркспейса при открытии папки и держит его в актуальном
состоянии (§7 [SPECIFICATION.md](../../../SPECIFICATION.md)). Модуль не
импортирует `vscode` и не имеет внешних зависимостей — тестируется в Node
(`tests/context-loader.test.mjs`).

```ts
const loader = new ContextLoader({
  root: workspace.path,
  homeDirectory: os.homedir(),   // для ~/.dsh/skills и ~/.dsh/AGENTS.md
  logger: (line) => output.appendLine(line)
});

const pack = await loader.load();          // кэш по хешу входов
const unsubscribe = loader.watch((next) => {
  panel.update(next);                      // hot reload с debounce 500 мс
});
// ...
unsubscribe();
loader.dispose();
```

## Что попадает в пак

| Поле | Источник |
|---|---|
| `rules` | `AGENTS.md` в корне и вложенных каталогах + файлы из `rules` манифеста (проект) + `~/.dsh/AGENTS.md` (пользователь); `depth` — близость к файлу |
| `manifest` / `manifestWarnings` | `.dsh/workspace.json` по схеме §4.3; битый JSON, неизвестные ключи, `rules`/`skills`/`memory.path` вне воркспейса или не найдены — предупреждения, сборка не падает |
| `skills` | `.agents/skills/*/SKILL.md`, `.dsh/skills/*/SKILL.md`, `~/.dsh/skills/*/SKILL.md` + каталоги из `skills` манифеста; имя/описание из YAML-фронтматтера |
| `memory` | `.dsh/memory/*.md`, если в манифесте `memory.enabled: true` (путь — `memory.path`); читается **только внутри воркспейса** — `../`, абсолютный путь снаружи и симлинк наружу отбрасываются (иначе `.md` с машины утёк бы в контекст агента) |
| `files` | индекс: путь, размер, язык, флаг `binary`; `.gitignore` + `context.ignore`, секреты и `.git`/`node_modules` исключены |
| `conflicts` | одинаковые имена скилов из проекта и пользовательских скилов: проект побеждает, проигравший виден инспектору (#013) |
| `stats` | число файлов, байты, разбивка по языкам, длительность, `truncated` |

### Приоритеты правил

`rulesFor(pack, relativePath)` возвращает правила, применимые к файлу: только
предки каталога, **ближайшее первым** (наследование по глубине), проект раньше
пользовательских. Конфликты не «затираются» молча: скилы попадают в
`conflicts`, а правила остаются все — решение о том, что показать, принимает
инспектор (#013).

### Игноры и секреты

- `.gitignore` в корне + `context.ignore` из манифеста; синтаксис gitignore:
  `*`, `**`, `?`, `dir/`, `!negation`, `/anchored`.
- Всегда исключены `.git` (и каталог, и файл — git worktree), `node_modules/`,
  `.pnpm-store/`.
- Секреты (`.env*`, `.npmrc`, `.netrc`, `id_rsa*`, `credentials*`, `*.pem`,
  `*.key`, `*.p12`, …) не попадают в индекс и не читаются. Тот же фильтр и
  realpath-границы применяются к `rules`/`skills` из манифеста: `.env`,
  `.git/config`, `node_modules/**` и симлинки наружу за воркспейс отбрасываются
  с предупреждением в `manifestWarnings`.
- Бинарники (картинки, архивы, шрифты, БД) индексируются без чтения содержимого
  с флагом `binary: true`.

### Лимиты

`context.maxBytes` (по умолчанию 262144) ограничивает суммарный размер файлов в
индексе и текстов правил/памяти: как только бюджет исчерпан, индекс обрезается,
`stats.truncated` = `true`. Лимит считается **в байтах** (UTF-8), а не в
UTF-16-символах; на границе многобайтного символа текст обрезается по границе
кодовой точки, поэтому лимит не превышается (U+FFFD не появляется). `maxFiles`
(по умолчанию 5000) страхует от гигантских деревьев.

## Кэш и hot reload

- Кэш по хешу входов: путь + `mtime` + `size` для индекса, правил (включая
  `AGENTS.md`, который не попал в индекс из-за игноров), скилов, манифеста и
  `.gitignore`. `loader.lastCacheHit` показывает, попал ли последний `load()` в
  кэш.
- `watch(listener)` — `fs.watch` с `recursive: true` и debounce 500 мс
  (`DEFAULT_DEBOUNCE_MS`); пересобирает пак только при изменениях релевантных
  файлов (`AGENTS.md`, `.gitignore`, `.dsh/**`, `.agents/skills/**`) и отдаёт
  новый пак наружу. Возвращает функцию отписки; `dispose()` закрывает watcher и
  сбрасывает кэш.
- Первая сборка на 1000 файлах укладывается в бюджет < 300 мс: обход дерева
  идёт одним проходом, `stat` синхронный (асинхронные 1000 `stat` через thread
  pool стоят сотни миллисекунд и нестабильны). Тест берёт лучший из трёх
  холодных прогонов: машина под параллельной нагрузкой (другие агенты,
  `pnpm install`) даёт случайные всплески I/O, не связанные с загрузчиком.

## Границы

- Панель/инспектор (`#013`) — потребитель `pack` и `conflicts`; здесь нет UI.
- Запуск сборки контекста при старте расширения и на смене воркспейса — #011;
  провайдер `WebviewView` — #005.
- Кэш не переживает перезапуск расширения: это память процесса.
