## Задача

Сделать из Kanban в VS Code настоящую доску, а не дерево, и показать состояние
канбан-плагина DSH.

Сейчас: `dsh.kanban` — `TreeView` (#014) с колонками-узлами и read-only
карточками; пользователь его «не видит» как доску. Настройка
`dsh.kanban.enabled` по умолчанию true, вкладка есть в контейнере DSH.

Нужно:
- `webview/src/kanban/`: колонки `backlog → todo → in-progress → in-review →
  testing → ready → merged` (+ blocked), карточки (id, title, owner, branch,
  updated, badge «в ветке»), счетчики, sticky-заголовки, горизонтальный скролл,
  темы light/dark;
- данные — парсер `.kanban/tasks/*.md` + доски worktree (как в GUI плагина);
  обновление через watcher файлов (debounce) + ручной refresh; без записи при
  простом просмотре;
- **статус плагина**: определить, активен ли `dsh-kanban` в профиле рантайма
  (проверка bundle в `~/.dsh/profiles/<profile>/package.json` или наличия
  host-сервиса); показывать:
  - «Kanban: плагин DSH активен — наряды рассылаются»;
  - «Kanban: плагин не установлен» + кнопки **«Установить»** (команда/инструкция
    из #035) и **«Работать со встроенной доской»** (остаться в read-only/или
    #037);
- пустое состояние: «В проекте нет `.kanban/tasks` — создать доску?» с командой
  `bin/task-new.sh` (если git-репозиторий) или инструкцией.

## Критерии готовности

- [ ] Доска рисуется как колонки с карточками текущего репозитория и обновляется
      при изменении карточек (тест рендера на фикстуре).
- [ ] Статус плагина виден и различает «активен / не установлен» (тест на двух
      фикстурах профиля).
- [ ] Кнопка «Установить» даёт точную команду `dsh plugin --profile <p> add`,
      «Работать со встроенной доской» скрывает баннер до перезагрузки.
- [ ] Пустое состояние с действием.
- [ ] Тёмная/светлая темы, горизонтальный скролл, доступность.

## Границы

Файлы задачи — только перечисленные. Общие файлы правит оркестратор.

## Уточнение от 18.11: рисовать как плагин

Доска в VS Code должна визуально повторять плагин `dsh-kanban`: колонки
`backlog…merged`, карточки с id, заголовком, бейджами `owner`/`branch`/«в ветке»,
временем; тёмная/светлая темы. Формат и совместимость — §17 `SPECIFICATION.md`.

## Уточнение от 18.11: доска встраивается в таб большой панели

Рендер доски должен быть **переиспользуемым компонентом**: одна и та же доска
показывается и в табе Board большой панели (#032), и (опционально) в сайдбаре.
Значит:
- вынести компонент доски в `webview/src/board/` с пропсами (данные, действия,
  тема, ширина);
- таб Board в большой панели — тот же компонент, но с полной шириной и
  горизонтальным скроллом колонок;
- статус плагина (активен/не установлен) — в шапке доски, одинаково в обоих местах.

## Сделано (`$(git rev-parse --short HEAD)`)

1. **Webview-доска** `webview/src/board/`: `boardModel.ts` (8 колонок
   backlog…merged+blocked в фиксированном порядке, счётчики, пустое состояние,
   бейджи owner/branch/«в ветке»), `Board.tsx` (sticky-заголовки, счётчики,
   горизонтальный скролл колонок, карточки id/title/owner/branch/updated,
   клик открывает файл, темы на `--vscode-*`, `role=list/listitem`, кнопки
   доступны с клавиатуры). Компонент переиспользуемый: данные через пропсы.
2. **Статус плагина** `views/kanbanPlugin.ts`: читает
   `~/.dsh/profiles/<profile>/package.json` (dependencies/devDependencies/
   optionalDependencies/plugins) и ищет `dsh-kanban`; возвращает installed,
   profile, точную команду `dsh plugin --profile <p> add @deepseek-ai/dsh-kanban`
   и причину. Баннер «плагин активен — наряды рассылаются» / «не установлен» +
   кнопки «Установить» (показывает точную команду) и «Работать со встроенной
   доской» (скрывает баннер до перезагрузки).
3. **Данные/обновление.** `dsh.kanban.openBoard` берёт колонки из
   существующего read-only парсера `.kanban/tasks` (включая worktree-копии),
   строит DTO всех 8 колонок и отправляет `boardOpen` в webview; ручной refresh
   перечитывает; watcher `**/.kanban/tasks/*.md` (debounce, #014) через
   `onColumns` обновляет открытую доску. Записи в `.kanban` нет.
4. **Пустое состояние** — «В проекте нет `.kanban/tasks` — создать доску?» с
   действием, которое показывает команду `bin/task-new.sh`.
5. **Тесты:** boardModel (8 колонок/счётчики/пусто/бейджи), статус плагина на
   двух фикстурах профиля, activation — `openBoard` отдаёт 8 колонок и статус,
   `boardInstall` показывает точную команду; manifest — команда.
