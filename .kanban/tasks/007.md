## Задача

Реализовать `SessionManager` — жизненный цикл сессий DSH из расширения.

- `extension/src/sessions/`: create/resume/list/pause через `DshBridge`.
- Хранение: активная сессия на воркспейс в реестре (#003), черновики — в
  `ExtensionContext.workspaceState` для восстановления после рестарта IDE.
- Восстановление: при активации — `session.resume` последней сессии; если сессия
  исчезла на стороне DSH — создаётся новая с записью причины в лог.
- Пауза: `turn.cancel`, сессия остаётся в списке; resume возвращает контекст.
- Команды `DSH: New Session`, `DSH: Resume Last Session`, `DSH: Stop Agent`.
- События наружу: `sessionChanged`, `statusChanged` (для статус-бара и панели).
- Тесты с мок-мостом: восстановление, отсутствующая сессия, гонка create/resume.

## Критерии готовности

- [ ] После рестарта Extension Host активная сессия восстанавливается без дублей.
- [ ] `DSH: Stop Agent` отменяет ход и оставляет сессию в списке.
- [ ] Тесты `node --test` зелёные.

## Заметки исполнителя

### Сделано (закоммичено в `task/007`, коммит `47c3675`)

Блокировка снята после merge #004: в ветке есть `DshBridge` и типы `protocol/`.

**`extension/src/sessions/sessionManager.ts`** — `SessionManager`:
- `restore()` — при активной сессии возвращает снимок (без дублей); иначе
  `session.resume` последней сессии из реестра, а при ошибке — `session.create`
  с причиной в лог; все публичные операции сериализуются, поэтому параллельные
  `restore()` не создают вторую сессию;
- `create()`, `resume(id)`, `list()`, `startTurn(input)`, `pause()`/`stop()`
  (через `turn.cancel`, сессия остаётся, статус `paused`), `getDraft()`/
  `setDraft()` в `workspaceState`;
- активная сессия пишется в реестр (#003) через порт `SessionPersistencePort`
  и дублируется в `workspaceState`; черновики — только в `workspaceState`;
- события `sessionChanged`/`statusChanged` со снимком (`sessionId`, `title`,
  `status`, `turnId`, `updatedAt`), подписка на `turn.done`/`error` моста;
- состояния `idle`/`restoring`/`active`/`paused`/`offline`;
- `dispose()` снимает подписки на мост.

**Порты и адаптеры:** `DshBridgePort` (подмножество API моста),
`MementoPort` (`workspaceState`), `SessionPersistencePort` +
`registryPersistence.ts` — адаптер к `WorkspaceRegistry`. `bridgePort.ts` —
статическая проверка `DshBridge extends DshBridgePort` (`pnpm typecheck` упадёт,
если мост разойдётся с портом).

**Команды:** `createSessionCommands()` — обработчики `DSH: New Session`,
`DSH: Resume Last Session`, `DSH: Stop Agent`; зарегистрированы в `activate()`
(заглушки для них убраны). Менеджер подключается через
`setSessionManager()`; до проводки в #011 команды честно сообщают «мост DSH не
подключён».

### Тесты — `tests/session-manager.test.mjs` (14)

`restore` без сохранённой сессии (создаёт), с сохранённой (resume, без create),
исчезнувшая сессия (create + причина в логе), гонка двух `restore` (resume один
раз), `create`/`list`, `stop` с `turn.cancel` и сохранением сессии, `pause` без

`SessionManagerError`), `dispose` без подписок, команды без менеджера и с ним,
адаптер реестра (read/write `lastSessionId`).
