## Задача

Дать расширению настоящий DSH-рантайм: сейчас `DshBridge` (#004) запускает
`dsh serve --protocol=jsonrpc --cwd <ws>`, но такого бинаря и режима не существует —
на машине `dsh` в PATH нет, а внутри приложения лежит Electron-рантайм.

Что известно (проверено оркестратором):

- в npm опубликован пакет `@deepseek-ai/dsh` **0.2.2-rc.1**; `bin: { dsh: lib/bin.js }`,
  `exports: ["./profile-boot", "./lib/*", "./package.json"]`;
- профили лежат в `~/.dsh/profiles/{web,desktop}` (package.json + node_modules),
  бандлы `@deepseek-ai/dsh-base`, `@deepseek-ai/dsh-web-app` + плагины;
- desktop-приложение поднимает Host-процесс из `profile-boot` — это рабочий путь.

Нужен спайк + реализация `DshRuntime`:

1. **Выбрать и обосновать маршрут** (ADR в `docs/adr/`):
   - (a) spawn `dsh` CLI из `@deepseek-ai/dsh` (какие команды есть у `lib/bin.js`:
     `web`, `serve`, `--port`, `--profile`), забрать порт/токен из stdout;
   - (b) дочерний Node-процесс, который делает `import("@deepseek-ai/dsh/profile-boot")`
     и поднимает профиль вручную (как приложение);
   - (c) подключение к уже запущенному приложению (не основной путь, только research).
2. **Реализовать запуск**: поиск бинаря (`dsh.executablePath` → PATH →
   `~/.dsh/profiles/*/node_modules/.bin/dsh` → `npx @deepseek-ai/dsh`),
   профиль из настройки (`dsh.profile`, по умолчанию `web`), spawn с cwd воркспейса,
   healthcheck, backoff, graceful shutdown (SIGTERM → SIGKILL), версия рантайма.
3. **Транспорт**: зафиксировать в `protocol/` реальный протокол (HTTP + WebSocket
   с токеном, либо stdio-мост к `profile-boot`), клиент `session.list`,
   `session.create`, `session.resume`, `turn.start`, `turn.cancel`.
   Существующий публичный API `DshBridge` сохранить — меняется только транспорт.
4. **Диагностика**: режим «рантайм не найден» — понятный экран с инструкцией
   (`npm i -g @deepseek-ai/dsh` или путь в настройке), без падения extension host;
   токен не пишется в логи.

## Критерии готовности

- [ ] Из Extension Host (интеграционный тест) рантайм поднимается, `session.list`
      возвращает список сессий профиля, `session.create` создаёт новую.
- [ ] Процесс корректно гасится по `dispose()`, дерево процессов пусто; повторный
      старт после падения — по backoff.
- [ ] Нет бинаря/профиля — состояние `failed` с текстом-инструкцией, extension host
      жив (проверить тестом).
- [ ] Версия рантайма проверяется и показывается в статусе; токен не логируется.
- [ ] ADR с выбором маршрута и оценкой рисков лежит в `docs/adr/`.

## Заметки исполнителя

### Спайк и ADR

Маршрут и риски — `docs/adr/0001-dsh-runtime.md`. Выбран **(b) `dsh --profile
acp`** — automation-only ACP-сервер по stdio NDJSON: формат кадра совпадает с
`DshBridge` (#004), авторизация/порты/cookie не нужны, процесс принадлежит
расширению. Маршрут (a) `dsh web` + HTTP/WebSocket Gateway отклонён
(token-exchange + cookie + WS + browser-envelope ради тех же методов), (c)
подключение к запущенному приложению — только research.

Спайк на реальном `@deepseek-ai/dsh@0.2.2-rc.1` (DSH_HOME во временном
каталоге) подтвердил: `initialize` → `protocolVersion 1`, `agentInfo.version
0.0.1`; `session/list` → `{sessions: []}`; `session/new` → sessionId;
`session/close` → сессия появляется в `session/list`; `session/resume` →
`configOptions` (для уже активной сессии ACP отвечает `session is already
active` — рантайм трактует это как успех); `session/cancel` — notification,
`session/prompt` завершается `stopReason: "cancelled"`.

### Сделано (закоммичено в `task/021`, коммит `d0fe1b7`)

**`extension/src/runtime/`** (без `vscode`, кроме типов):
- `discovery.ts` — поиск бинаря: `dsh.executablePath` (явный путь без
  fallback) → PATH → `~/.dsh/profiles/<profile>/node_modules/.bin/dsh` → `npx
  @deepseek-ai/dsh`; инструкция «не найден»; `redactSecrets` для логов;
- `acpPeer.ts` — NDJSON JSON-RPC 2.0 клиент (id-корреляция, таймауты,
  уведомления, отказ на запросы агента);
- `acpProtocol.ts` — маппинг: `session.list/create/resume` ↔
  `session/list/new/resume`, `turn.start` ↔ `session/prompt` (turnId
  возвращается сразу, результат — `turn.done`), `turn.cancel` →
  notification `session/cancel`, `session/update` → `token`/`tool.call`/
  `tool.result`;
- `acpRuntime.ts` — супервизор: spawn с cwd воркспейса, `initialize`, версии
  (`dsh` из package.json установки + ACP agentInfo), backoff-рестарт
  (экспоненциальный, до 5 попыток), SIGTERM → SIGKILL, `diagnostics` с
  инструкцией, состояние `failed` без падения extension host; `request/on/
  start/stop` — порт `DshBridgePort`, поэтому `SessionManager` (#007)
  подключает рантайм без изменений.

**Манифест:** `dsh.profile` (string, default `acp`). Отличие от текста карточки
(`web`) обосновано ADR: профиль `web` — это HTTP GUI, для расширения выбран
`acp`; значение настраивается.
