## Задача

Сделать видимую панель DSH в VS Code: контейнер в activity bar и WebView чата.

- `contributes.viewsContainers.activitybar` с иконкой DSH и view `dsh.chat`.
- `extension/src/views/chatViewProvider.ts`: `WebviewViewProvider`, CSP с nonce,
  загрузка `webview/dist`, обработка сообщений webview ↔ extension.
- `webview/`: React-приложение: шапка (имя воркспейса, модель, sandbox, кнопка
  «Стоп»), лента (пустое состояние с подсказкой), composer (многострочный ввод,
  Enter/Shift+Enter), статус-строка панели.
- Темы — только через `--vscode-*` переменные; светлая и тёмная проверены.
- Доступность: фокус, клавиатурная навигация, ARIA-роли, контраст.
- i18n-каркас: строки вынесены в `webview/src/i18n` (ru/en).

## Критерии готовности

- [ ] View открывается в activity bar, рендерится без ошибок CSP в консоли.
- [ ] Composer отправляет сообщение в extension по `postMessage` (эхо в ленте).
- [ ] Переключение light/dark темы в VS Code не ломает контраст (скриншот/проверка).
- [ ] Webview-сборка валит `pnpm build` при ошибке типов.

## Заметки исполнителя

### Сделано (закоммичено в `task/005`, коммит `e07ba04`)

**Манифест (`extension/package.json`)** — контейнер и view:

- `contributes.viewsContainers.activitybar`: `{ id: "dsh", title: "DSH", icon: "media/dsh.svg" }`;
- `contributes.views.dsh`: `{ id: "dsh.chat", name: "Chat", type: "webview" }`;
- иконка `extension/media/dsh.svg` (монохромная, красится темой).

**`extension/src/views/chatHtml.ts`** — чистая часть без `vscode`:
`parseWebviewMessage` (валидация `ready`/`sendMessage`/`stop`), `extractViteAssets`
(скрипт и стили из собранного `index.html`), `renderChatViewHtml` (CSP с nonce,
внешние ассеты, без инлайновых скриптов), `renderChatViewNoticeHtml` (заглушка,
если WebView не собран), `escapeHtml`.

**`extension/src/views/chatViewProvider.ts`** — `WebviewViewProvider`:
- `localResourceRoots` = `extension/dist/webview`, ассеты через `asWebviewUri`;
- CSP: `default-src 'none'`, `script-src 'nonce-…'`, `style-src <cspSource> 'unsafe-inline'`, nonce случайный на каждый рендер;
- читает `index.html` через `vscode.workspace.fs` (работает и в remote);
- `retainContextWhenHidden: true` — лента не теряется при переключении вкладок;
- сообщения: `ready` → `state` (+ `replaceMessages`), `sendMessage` → эхо
  «пользователь + ответ», `stop` → статус `stopped`; сообщения не по схеме
  отбрасываются и логируются;
- `appendMessage()`/`postMessage()` — точка входа для #008;
- панель регистрируется в `activate()` (`registerWebviewViewProvider`).

**`webview/`** — React-приложение панели: `Header` (воркспейс, модель, sandbox,
«Стоп»), `MessageList` (пустое состояние, автоскролл, `role="log"` +
`aria-live`), `Composer` (textarea, Enter — отправить, Shift+Enter — новая
строка, подписи для скринридера), `PanelStatus` (состояние, токены/время —
каркас), `i18n/index.ts` (словари ru/en, `resolveLocale`), `vscodeApi.ts`
(обёртка `acquireVsCodeApi` + `message`), `messages.ts` (контракт).
Темы — только `--vscode-*` переменные; фокус через `--vscode-focusBorder`;
`prefers-reduced-motion`.

**Сборка WebView в расширение.** `webview/scripts/copy-dist.mjs` (шаг
`webview build`) копирует `webview/dist` → `extension/dist/webview`: панель ищет
ассеты относительно `context.extensionUri`, иначе они не найдутся ни в EDH, ни в
будущем VSIX. Без этой копии `vsce` не упаковал бы WebView вовсе (сейчас
`vsce ls` показывает `dist/webview/index.html` и ассеты).
