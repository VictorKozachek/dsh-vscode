## Задача

Реализовать `WorkspaceResolver` — компонент, который по открытой папке говорит,
какой это воркспейс и как его опознать между запусками.

- `extension/src/workspace/resolver.ts`: `resolveWorkspace(folders)` →
  `{ id, path, name, remote, gitRemote, multiRoot, primary }`.
- Канонический путь: `fs.realpath`, нормализация регистра на `darwin`/`win32`,
  учёт смены раскладки.
- `gitRemote`: чтение `.git/config` без внешних зависимостей; нормализация
  `git@github.com:org/repo.git` → `github.com/org/repo`; поддержка `git worktree`.
- `remote`: `vscode.env.remoteName` (`ssh`/`wsl`/`containers`) как часть ключа.
- `id`: `sha256(remote | path | gitRemote)[:16]`; стабилен при переезде папки в
  пределах той же машины, если `gitRemote` совпадает.
- Multi-root: primary — первая папка; `.code-workspace` определяется.
- Unit-тесты на временных каталогах: без открытой папки, одиночный корень,
  вложенные папки, симлинк, смена регистра, git-репозиторий без remote.

## Критерии готовности

- [ ] `resolveWorkspace` возвращает стабильный `id` для одного и того же проекта
      при повторных вызовах и после рестарта.
- [ ] Ни одного `child_process` вызова на горячем пути: только чтение файлов.
- [ ] Тесты покрывают все перечисленные случаи; `node --test` зелёный.
- [ ] Публичный API задокументирован в `extension/src/workspace/README.md`.

## Заметки исполнителя

### Сделано (закоммичено в `task/002`)

- `extension/src/workspace/resolver.ts` — `resolveWorkspace(folders, options?)`
  (`{ id, path, name, remote, gitRemote, multiRoot, primary, folders,
  codeWorkspaceFile }`, `null` без открытых папок) плюс вспомогательные
  экспорты: `canonicalizePath`, `normalizePathForKey`, `normalizeRemoteName`,
  `workspaceId`, `normalizeGitRemote`, `parseGitConfigRemoteUrl`,
  `readGitRemote`, `LOCAL_REMOTE`.
- Канонизация пути: `fs.realpath` (симлинки), NFC (раскладка/Unicode),
  нормализация регистра в ключе на `darwin`/`win32`.
- `gitRemote`: `.git/config` разбирается вручную, без `child_process`;
  поддержаны вложенные папки (подъём вверх), `.git`-файл git worktree
  (`gitdir` + `commondir`), `origin` приоритетнее прочих remote; URL
  нормализуется до `host/org/repo` (`git@…:`, `ssh://`, `https://` с
  креденшелами).
- `remote` — из `options.remoteName` (`vscode.env.remoteName`); пусто → `local`.
- `id`: `sha256[:16]` от `remote|gitRemote`, а при отсутствии git-remote — от
  `remote|канонический путь`. Так `id` совпадает у одного и того же проекта,
  склонированного/перемещённого в другое место (требование задачи), и при этом
  разные папки без git не склеиваются. Это осознанный выбор против буквальной
  формулы `sha256(remote | path | gitRemote)`: с путём в ключе требование о
  стабильности при переезде невыполнимо. Задокументировано в
  `extension/src/workspace/README.md`.
- `extension/src/workspace/README.md` — публичный API, ключ и `id`, границы.
- `tests/workspace-resolver.test.mjs` — 17 тестов на временных каталогах: без
  папки, одиночный корень, повторные вызовы, remote в ключе, вложенная папка в
  репозитории, git без remote, симлинк, смена регистра, переезд папки с тем же
  `gitRemote`, git worktree, multi-root + `.code-workspace`, таблица форм
  remote-URL, разбор `.git/config`, NFC, отсутствие запуска процессов.
