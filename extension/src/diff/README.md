# `extension/src/diff` — DiffService (#010)

Правки показываются диффом до применения, применяются одной транзакцией с
проверкой конфликта и откатываются (`DSH: Revert Last Edit`).

| Файл | Что делает |
|---|---|
| `diffService.ts` | ядро без `vscode`: нормализация правок, границы воркспейса, хеши, предпросмотр/применение/откат, строчный diff |
| `diffController.ts` | контроллер без `vscode`: точное применение через порт `DiffEditorPort`, проверка результата, откат |
| `diffEditor.ts` | VS Code-редактор: `vscode.diff` через виртуальный документ, `WorkspaceEdit` (полная замена, undo), сообщения |

## Правки

- `replaceFile` — полная замена содержимого;
- `replaceText` — точечная замена фрагмента (неоднозначность — ошибка, если не
  передан `all: true`);
- `replaceLines` — замена диапазона строк (1-based, включительно; `endLine =
  startLine - 1` — вставка).

```ts
const diff = new DiffService({ workspaceRoot });
const preview = await diff.preview([
  { path: 'src/app.ts', operations: [{ kind: 'replaceText', find: 'a = 1', replace: 'a = 2' }] }
]);
// preview.files[0].textEdits — минимальные замены строк для vscode.diff

const result = await diff.apply(preview.id);   // 'applied' | 'conflict' | 'failed'
await diff.revertLast();                        // 'reverted' | 'conflict' | 'empty'
```

## Гарантии

- **Предпросмотр не пишет файлы.** Он считает новые содержимые, хеши
  (`sha256`) и минимальные строчные правки.
- **Конфликт не затирает чужие изменения.** `apply` сначала сверяет хеши всех
  файлов; расхождение → `{ status: 'conflict', path }` без единой записи.
  `revertLast` так же сверяет применённое содержимое.
- **Транзакция.** При ошибке записи середины пачки уже записанные файлы
  возвращаются к исходному содержимому (`status: 'failed'`).
- **Границы.** Правка вне корня воркспейса (`../`, абсолютный путь снаружи,
  симлинк наружу) отклоняется `DiffServiceError` с кодом `outside-workspace`.
  Проверка идёт через `DiffFileSystem.probePath` (`lstat` + `realpath` в
  node-адаптере): `ok`/`missing`/`blocked`. Для нового пути ищется ближайший
  существующий предок, остаток приклеивается; **битая ссылка** и ошибка
  lstat/realpath (`blocked`) — fail-closed, а не отступление к предку.
  Кастомный `DiffFileSystem` без `probePath` даёт только легаси-поведение
  (`realpath`-null неотличим от отсутствия) — для строгой границы обязателен
  `probePath`.
- **Конфликт существования.** Для существовавшего файла проверяется наличие и
  хеш, для нового — что он не появился между preview и apply (пустой файл тоже
  считается изменением).
- **Дубли путей** в одной пачке объединяются: операции применяются по порядку,
  пишется одна запись.
- **Откат (`DSH: Revert Last Edit`) транзакционен:** созданные файлы
  удаляются (а не остаются пустыми), ошибка в середине возвращает уже
  откатанные файлы к применённому содержимому (`status: 'failed'`).
- Новые файлы создаются, а откат удаляет их (при наличии `removeFile` в порту).

## VS Code

`DiffController` (создаётся в #011, когда известен воркспейс):

1. `preview(edits)` — открывает `vscode.diff` «файл на диске ↔ виртуальный
   документ» (схема `dsh-diff`, содержимое по хешу), файлы не меняются;
2. `apply(previewId)` — проверяет хеши и применяет **всю пачку одним
   `WorkspaceEdit`** (точный `newContent`, полная замена документа; для новых —
   `createFile`). Сбой пачки означает «ничего не применено». Если после
   применения фактическое содержимое не совпало с `newContent`, контроллер
   **ничего не перезаписывает** (расхождение может быть чужой правкой) —
   сообщает конфликт и оставляет файлы пользователю/undo редактора; `markApplied`
   вызывается только после успешной сверки. Undo возвращает исходное
   (включая `\n` и CRLF);
3. `revertLastEdit()` — `DSH: Revert Last Edit` (команда объявлена в манифесте
   и зарегистрирована в активации; контроллер подключается через
   `setDiffController`, редактор — `VscodeDiffEditor`).
