## Задача

Расширение запускает `dsh` без учёта того, что VS Code из GUI на macOS имеет
урезанный PATH. `dsh` — Node-скрипт с shebang `#!/usr/bin/env node`, поэтому
spawn падает с `env: node: No such file or directory` и кодом 127:
ACP не поднимается, панель показывает «менеджер сессий не подключён».

Диагностика из `Output → DSH` (VSIX dev7, 18.11):

```
ACP: запуск /opt/homebrew/bin/dsh (setting)
ACP stderr: env: node: No such file or directory
ACP: процесс завершился (127), перезапуск через 500 мс (попытка 1/5)
```

**Требования:**
1. При spawn передавать окружение, в котором `PATH` содержит каталог Node,
   которым работает расширение: `path.dirname(process.execPath)` в начало PATH
   (и не терять остальной PATH пользователя). Это чинит случай, когда
   `dsh.executablePath` указывает на скрипт с `env node`, а node нет в GUI PATH.
2. Если `dsh` — скрипт с shebang `#!/usr/bin/env node`, а node всё равно не
   находится — попробовать запуск через `process.execPath` (node dsh ...) как
   fallback, с записью в диагностику.
3. Диагностика: показывать, какой node/PATH использованы при spawn, и подсказку
   «укажите путь к node/dsh» вместо голого кода 127.
4. Тест: spawn с пустым PATH (`env -i`) + `dsh`-скрипт с `env node` — процесс
   стартует (мок-бинарь), без 127; тест на fallback через process.execPath.
