## Задача

Подтверждения и sandbox-политики: инлайн-диалоги вместо модальных окон.

- `webview/src/approvals/`: инлайн-карточка `approval.request` с кнопками
  «Разрешить», «Разрешить для этой сессии», «Отклонить», «Показать diff»;
  фокус-ловушка и клавиатура.
- `extension/src/approvals/`: политика `ask`/`auto`/`never` (per tool type),
  маппинг sandbox-режимов `read-only`/`workspace-write`/`danger-full-access`,
  обязательное подтверждение для записи вне воркспейса и сетевых вызовов.
- Аудит: `.dsh/audit.log` (JSONL, ротация по размеру), без секретов.
- Fallback: если панель скрыта — `vscode.window.showInformationMessage` с теми же
  действиями (не блокирующий модал).
- Тесты: разрешение политик, отклонение останавливает инструмент, аудит-запись.

## Критерии готовности

- [ ] «Отклонить» гарантированно останавливает инструмент (тест).
- [ ] `ask` для записи вне воркспейса даже при `auto` (тест).
- [ ] Аудит пишется, ротация работает, секретов нет.
- [ ] Тесты зелёные.

## Заметки исполнителя

### Сделано (закоммичено в `task/009`, коммит `5d16c96`)

**`extension/src/approvals/`** (модули без `vscode`, покрыты тестами):
- `approvalPolicy.ts` — матрица `allow`/`ask`/`deny`: `ask`/`auto`/`never`,
  per-tool переопределения, `parseSandboxMode`, `toDshSandboxArguments`,
  `isPathInsideWorkspace`; запись вне воркспейса и сетевые вызовы требуют
  подтверждения **даже при `auto`**, при `never` — запрещаются; sandbox
  `read-only` запрещает запись и команды;
- `approvalBroker.ts` — очередь pending, «Разрешить для этой сессии»
  (запоминается для пары сессия+инструмент), решения из WebView
  (`resolve`/`showDiff`), `dispose()` закрывает pending как `deny`;
- `auditLog.ts` — JSONL `.dsh/audit.log` (права 0600), ротация по размеру
  (`maxBytes` 1 МБ, `maxFiles` 3), рекурсивная фильтрация секретов (ключи
  `token`/`secret`/`password`/`apiKey`/`auth`/…, userinfo из URL);
- `fallback.ts` — `showInformationMessage` с теми же тремя действиями, если
  панель скрыта; закрытие уведомления трактуется как отказ.

**`webview/src/approvals/`**:
- `approvalModel.ts` — чистая логика карточки: действия, фокус-ловушка
  (`nextFocusIndex`), клавиатура (Esc → «Отклонить», Enter → действие под
  фокусом, Tab/стрелки по кругу), форматирование аргументов, признак diff;
- `ApprovalCard.tsx` — инлайн-карточка `role="alertdialog"`,
  `aria-modal="false"`, фокус на первой кнопке, клавиатурная навигация; текст
  аргументов — обычный React-узел (без raw HTML);
- `App.tsx` показывает карточки из `approvalRequest` и убирает по
  `approvalResolved`; кнопки шлют `approvalResolve`/`approvalShowDiff`.

**Контракт сообщений** расширен синхронно в `chatHtml.ts` и
`webview/src/messages.ts` (`approvalRequest`, `approvalResolved`,
`approvalResolve`, `approvalShowDiff`); диспетчер панели маршрутизирует
approval-сообщения в порт `approvals` (брокер), каркас их не обрабатывает.
