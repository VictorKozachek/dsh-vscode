## Задача

Реализовать `SessionManager` — жизненный цикл сессий DSH из расширения.

- `extension/src/sessions/`: create/resume/list/pause через `DshBridge`.
- Хранение: активная сессия на воркспейс в реестре (#003), черновики — в
  `ExtensionContext.workspaceState` для восстановления после рестарта IDE.
- Восстановление: при активации — `session.resume` последней сессии; если сессия
  исчезла на стороне DSH — создаётся новая с записью причины в лог.
- Пауза: `turn.cancel`, сессия остаётся в списке; resume возвращает контекст.
- Команды `DSH: New Session`, `DSH: Resume Last Session`, `DSH: Stop Agent`.
- События наружу: `sessionChanged`, `statusChanged` (для статус-бара и панели).
- Тесты с мок-мостом: восстановление, отсутствующая сессия, гонка create/resume.

## Критерии готовности

- [ ] После рестарта Extension Host активная сессия восстанавливается без дублей.
- [ ] `DSH: Stop Agent` отменяет ход и оставляет сессию в списке.
- [ ] Тесты `node --test` зелёные.

- `dispose()` снимает подписки на мост.

## Исправления по замечаниям ревьювера (`a3a6682`)

1. **`restore` больше не смешивает `session.resume` и запись в реестр.**
   Bridge-операция и persistence разделены: успешный resume ставит `active`;
   ошибка записи логируется внутри `#persistSession` и не переводит менеджер в
   `offline` и не создаёт вторую сессию. То же в `#createLocked`/`resume(id)`:
   `session.create` успешен → сессия активна даже при EACCES в реестре.
2. **Временные ошибки resume не превращаются в дубль.** После ошибки `resume`
   менеджер проверяет `session.list`: сессия есть → `SessionManagerError`
   (статус `idle`, без `create`); `session.list` недоступен → ошибка «мост
   недоступен» (`offline`, без `create`); сессии действительно нет → создаётся
   новая с причиной в лог.
3. **В реестр пишется текущее время открытия.** `#persistSession` сам берёт
   `clock()` (а не `#updatedAt` конструктора/предыдущего события) — сортировка и
   GC реестра #003 получают корректный `lastOpenedAt`; тест с тикающими часами.
4. **`stop()`/`pause()` не врут при отказе `turn.cancel`:** статус остаётся
   `active`, `turnId` сохраняется, бросается `SessionManagerError` — команда
   покажет ошибку, а не «Остановлено».
5. **README исправлен:** убрано обещание «двойной клик New Session не создаёт
   дублей» — идемпотентен `restore`, а `create()` (команда New Session) —
   осознанное действие и всегда создаёт новую сессию. Добавлен раздел
   «Устойчивость».
