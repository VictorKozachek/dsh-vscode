## Задача

Поднять монорепозиторий расширения и минимальную сборку, на которой дальше
работают все остальные задачи.

- `package.json` (корень): pnpm workspaces, скрипты `build`, `test`, `lint`;
  `packageManager` зафиксирован.
- `tsconfig.base.json`: строгий TS (strict, noUncheckedIndexedAccess), target
  ES2022, module NodeNext.
- `extension/`: `package.json` манифеста (`name: dsh-vscode`,
  `engines.vscode`, `main: ./dist/extension.js`, `activationEvents:
  ["onStartupFinished"]`), `contributes.commands` (каркас команд из §10 спеки),
  `contributes.configuration` (ключи `dsh.*` из §9), `src/extension.ts` с
  активацией: статус-бар `DSH · <workspace> · idle`, регистрация команд-заглушек.
- `webview/`: каркас React + Vite (страница-заглушка), сборка в `webview/dist`.
- `protocol/`: пустой пакет типов с `tsconfig` и `index.ts` (наполнит #004).
- `tests/`: каркас тестов на `node --test`.
- esbuild-конфиг сборки extension host; `extension/dist` и `webview/dist` — в `.gitignore`.

## Критерии готовности

- [ ] `pnpm install && pnpm build` завершается с кодом 0 на чистом клоне.
- [ ] `node --test` проходит (хотя бы один smoke-тест на импорт модуля).
- [ ] `extension/package.json` — валидный JSON, проходит `vsce ls --no-dependencies`
      или эквивалентную проверку манифеста.
- [ ] В Extension Development Host расширение активируется, статус-бар показывает
      имя открытой папки, команда `DSH: New Session` вызывается без ошибок.
- [ ] `extension/dist/extension.js` собирается одним файлом (без внешних require
      на workspace-пакеты).

### Среда: реестр npm

`~/.npmrc` указывает на внутренний CodeArtifact, который отвечает 401, поэтому
установка в этой среде идёт с явным реестром:
`pnpm install --registry=https://registry.npmjs.org/`. В `pnpm-workspace.yaml`
выключен `verifyDepsBeforeRun`: проверка зависимостей перед `pnpm run` тянет
метаданные из реестра `~/.npmrc` и падает с 401, из-за чего не запускался бы ни
один скрипт. Это стоит пересмотреть, когда починят токен внутреннего реестра
(кандидат в задачу #017 вместе с CI).

(`code --extensionDevelopmentPath=extension`) требует GUI и в CI/worktree не
