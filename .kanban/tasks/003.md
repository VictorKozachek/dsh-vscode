## Задача

Реализовать `WorkspaceRegistry` — локальный реестр воркспейсов, который
переживает рестарты IDE и не хранит секретов.

- `extension/src/workspace/registry.ts`: `~/.dsh/workspaces/<id>.json`
  (путь настраивается `dsh.workspace.registryPath`), схема из §4.2 спеки:
  `id, path, remote, gitRemote, name, lastOpenedAt, lastSessionId, defaultModel,
  sandboxMode, approvalPolicy, contextSnapshot`.
- Атомарная запись: temp-файл + `rename`, права `0600`.
- Версионирование схемы и миграции `vN → vN+1` при чтении.
- GC: удаление записей, не открывавшихся N дней (`dsh.workspace.keepDays`,
  по умолчанию 90); команда `DSH: Prune Workspaces`.
- Фильтрация секретов: ключи/token/secret в любом регистре не пишутся.
- Тесты: конкурентная запись, битый JSON (карантин файла), миграция с v1, GC,
  отсутствие прав на запись — понятная ошибка без падения.

## Критерии готовности

- [ ] Реестр читается/пишется атомарно; при битом файле воркспейс создаётся заново,
      файл уходит в `<id>.json.corrupt-<ts>`.
- [ ] Тесты на временном `HOME`; `node --test` зелёный.
- [ ] В реестре нет секретов (проверка тестом на список запрещённых ключей).

## Заметки исполнителя

### Сделано (закоммичено в `task/003`)

- `extension/src/workspace/registry.ts` — класс `WorkspaceRegistry`:
  `save`, `remember` (upsert с сохранением полей), `read`, `list`, `touch`,
  `remove`, `prune`; схема §4.2 + `version`.
- Атомарная запись: временный файл `.‹id›.json.tmp-‹pid›-‹n›-‹rand›` в том же
  каталоге + `rename`, права `0600`.
- Версионирование: `REGISTRY_SCHEMA_VERSION = 2`, миграция v1 → v2 при чтении
  (`lastOpenedAt` из мс в ISO, `remote` → `local`, `gitRemote`/`contextSnapshot`
  → `null`). Файл более новой версии схемы **не читается и не карантинится** —
  чтобы старая сборка не портила данные новой.
- Битый JSON / не по схеме → `<id>.json.corrupt-<ts>` (без коллизий по имени),
  `read` возвращает `null`, следующая запись создаёт воркспейс заново.
- GC: `prune(keepDays?)` удаляет записи, не открывавшиеся дольше срока (и с
  нечитаемой датой); срок — `dsh.workspace.keepDays` (по умолчанию 90).
- Секреты: ключи `token/secret/password/apiKey/auth/credential/privateKey` в
  любом регистре вырезаются рекурсивно, креденшелы из URL-строк вычищаются
  (`https://user:token@host` → `https://host`), неизвестные поля верхнего
  уровня не пишутся. `stripCredentials` экспортирован.
- `assertWorkspaceId`: `id` — 16 hex; защищает от выхода за пределы каталога
  (`../../etc/passwd` отвергается).
- Ошибки — `WorkspaceRegistryError` с понятным сообщением (нет прав на запись,
  некорректный id, некорректный срок GC); процесс не падает.
- `extension/src/workspace/registry.md` — схема, API, политика карантина,
  секретов и GC.
- `tests/workspace-registry.test.mjs` — 14 тестов на временных каталогах:
  запись/чтение, права `0600`, конкурентная запись (24 параллельных `save`, без
  временных файлов), карантин битого JSON, файл будущей версии, миграция v1,
  GC, отсутствие прав на запись, фильтрация секретов, проверка `id`, каталог по
  умолчанию из временного `HOME` + `~`, сортировка списка, `touch`/`remember`,
  `remove` и константы.

### Команда и настройка (файлы вне `workspace/`)

Карточка требует команду `DSH: Prune Workspaces` и настройку
`dsh.workspace.keepDays`, поэтому пришлось тронуть файлы из #001:

- `extension/package.json` — команда `dsh.pruneWorkspaces` и настройка
  `dsh.workspace.keepDays` (number, default 90, minimum 1);
- `extension/src/extension.ts` — регистрация команды: читает
  `dsh.workspace.registryPath`/`dsh.workspace.keepDays`, вызывает
  `registry.prune()`, показывает результат, удалённые id пишет в канал `DSH`;
- `tests/manifest.test.mjs` — тест больше не требует ровно 8 команд §10:
  проверяет, что все команды §10 на месте, а сверх них допустимы только
  известные служебные (`extraCommands`); в настройки добавлен `keepDays`
  (помечено, что он не из §9);
- `tests/activation.test.mjs` — заглушка `vscode` получила
  `workspace.getConfiguration` и `window.showErrorMessage`, в список команд
  добавлен `dsh.pruneWorkspaces`, новый тест вызывает команду на временном
  реестре и проверяет, что старая запись удалена.

Если по политике #003 не должна трогать эти файлы — скажи, вынесу проводку в
